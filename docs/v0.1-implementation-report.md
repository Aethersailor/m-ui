# m-ui v0.1 实现报告

本报告描述当前 `codex/publisher-reconciliation` 工作树中的统一 v0.1 实现。发布
身份、Actions Run、构建产物和 `debian-sid` 运行证据以最终 SHA 对应的报告为准；
仓库不保存二进制、包、镜像 tar、数据库或日志。

## 实现范围

- 单机、单管理员、Linux amd64/arm64 的 Mihomo 管理。
- VLESS over TCP、REALITY、XTLS Vision；数据库是业务事实来源，YAML 是确定性产物。
- 受管 Mihomo 内核的 `release` 与滚动 `alpha` 渠道、身份/摘要校验、原子激活、健康检查和自动回滚。
- systemd（Debian 12+/sid、Ubuntu）、OpenRC（Alpine）和非 root Docker managed supervisor。
- CLI、认证/CSRF 管理 API、System/Runtime 内核卡片、定时更新 scheduler、统一部署脚本和 GoReleaser/nFPM 发行定义。

## Fail-closed 与并发安全

启动 reconciliation 在清除 degraded 失败后释放原 context，并使用独立的 5 秒补偿 context。补偿成功返回可识别的 `ErrStartupDegraded`；补偿失败返回不包装该 sentinel 的致命错误。App 层重新读取持久化状态，错误与状态不一致时拒绝启动 HTTP、expiry scheduler 和其他写入 runner。

配置发布、配置回滚、启动恢复、runtime action、内核更新和内核回滚共用可取消的协调器，并在 Linux 上使用受保护的跨进程 flock。发布和内核状态均保留 COMMIT/manifest 一致性、fsync、原子 rename、回滚和 degraded 语义。

## Mihomo 内核治理

上游客户端固定为 `MetaCubeX/mihomo` 官方 GitHub API 和 Release 资产域名。release 严格排除 draft/prerelease，alpha 使用 `Prerelease-Alpha`；身份包含 release ID、tag、发布时间、asset ID、资产大小、资产 SHA-256、目标 commit 和实际 CLI 版本。支持 ETag、连接/响应/下载大小限制、可信 HTTPS 重定向、可选 `M_UI_GITHUB_TOKEN`，token 和下载 URL 不进入状态、日志、审计或前端。

当前内核位于 `/var/lib/m-ui/core/current/mihomo`，staging/backups 在同一受管目录中。候选必须通过 gzip、文件类型/owner/mode/大小、资产 digest、`mihomo -v` 和当前配置 `-t -f`；激活后重启并读取实际运行版本。失败时保留旧版本或自动恢复，回滚失败才进入 degraded；成功备份保留最近两个。外部 binary 可被 adopted，但外部模式只读且禁止自动更新。

## 部署、发行和容器

`.goreleaser.yaml` 是原生 tar/deb/apk、SHA256SUMS 和 SBOM 的单一构建定义，支持静态 Linux amd64/arm64；bootstrap Mihomo 身份由 workflow 动态锁定并在两个架构、包和镜像间复用。`scripts/manage.sh` 提供 install/update/reinstall/uninstall/purge/status/doctor，显式校验 HTTPS、SHA-256、tar 路径/类型并保留数据；package lifecycle 在升级失败时恢复程序文件。

Docker 镜像使用 Node/Go 多阶段构建、Alpine 最小运行时、UID 10001、Tini、host-network Compose 示例和 `CAP_NET_BIND_SERVICE`，容器内 m-ui 直接监督 Mihomo，healthcheck 同时检查管理 API 和 `core status`。镜像不运行 systemd，不含源码、编译工具、缓存或 token。

`.github/workflows/build-release.yml` 是唯一 Actions 入口，固定 action/tool 版本并覆盖 Go test/vet/race、前端 lint/typecheck/test/build、真实 Mihomo smoke、ShellCheck、actionlint、hadolint、systemd/sudoers、部署脚本、原生 amd64/arm64 包和非 root Docker 验证。普通 push/PR 只测试；手动 `build` 上传完整产物但不发布；手动 `release` 才创建 annotated tag、attestation、GitHub Release 以及仅含版本号和 `latest` 的 GHCR 多架构镜像标签。

## 安全边界

m-ui、Mihomo 和 Docker managed supervisor 均以非 root 身份运行；面板默认回环监听，Controller 仅回环并认证，浏览器 mutation 需要 Session 与 CSRF。配置、数据库敏感字段使用类型化结构和加密存储；日志/审计禁止密码、Controller secret、REALITY 私钥、完整 UUID、完整分享链接、Session/CSRF token 和请求体。安装与升级不修改 SSH、防火墙、反向代理或 Cloudflare。
